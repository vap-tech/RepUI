# Autocomplete: подтверждённое значение и свободный ввод

## Проблема

Текущий Autocomplete позволяет напечатать произвольный текст и оставить его
после ухода фокуса. Это смешивает его контракт с Combobox.

Autocomplete должен выбирать существующий option. Свободное значение должно
быть отдельной возможностью Combobox.

## Что должно происходить

- ввод фильтрует options, но сам по себе не меняет committed value;
- `Enter` подтверждает активный option;
- клик или pointer activation по option подтверждает option;
- `Escape` отменяет текущий ввод и возвращает последнее подтверждённое значение;
- `Tab` не должен отправлять произвольный текст как значение;
- уход фокуса без выбора должен либо вернуть последнее подтверждённое значение,
  либо очистить поле, если значения ещё не было;
- hidden input меняется только после подтверждения option;
- событие `rui:autocompletechange` отправляется только после подтверждения.

## Почему нельзя просто откатывать значение в blur

`blur` может происходить во время выбора option из popup. В этот момент
Autocomplete ещё не получил `click`/pointer activation, поэтому ранний откат
стирает ввод или выбранное значение до завершения выбора.

Также popup переносится через `OverlayPortal`, а фокус и события могут идти
между input, overlay и option. Поэтому простой `setTimeout` в blur создаёт
гонки и нестабильное поведение.

## Предлагаемая реализация

Разделить состояния:

```text
inputValue       — текущий текст поиска;
committedValue   — последнее подтверждённое value;
committedLabel   — отображаемая подпись подтверждённого option;
activeOption     — текущий option для keyboard navigation.
```

Добавить явные методы runtime:

```js
commitOption(option, originalEvent)
cancelInput()
restoreCommittedValue()
handleFocusOut(event)
```

`handleFocusOut` должен сначала определить, уходит ли фокус внутрь Autocomplete
или его popup. Отмена/восстановление выполняется только когда фокус действительно
покинул весь composite-контрол.

Выбор option должен обрабатываться на `pointerdown` или через единый activation
handler, чтобы commit произошёл до blur input. Нативный `click` можно оставить
для клавиатурной совместимости, но он не должен дублировать commit.

## Проверки в Workbench

- произвольный ввод временно фильтрует options;
- ввод без выбора не меняет hidden input;
- `Enter` подтверждает active option;
- клик по option подтверждает option;
- `Escape` возвращает прежнее значение;
- `Tab` не отправляет неподтверждённый текст;
- уход фокуса за пределы composite-контрола восстанавливает committed value;
- переход фокуса из input в popup не вызывает отмену;
- HTMX refresh сохраняет committed value.
